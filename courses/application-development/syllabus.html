Module-by-Module Curriculum

Module 1:Programming Basics with Dart

Weeks 1-3

Core Topics

  • What an app is, how a phone runs it, and what a developer actually does
  • Setting up the laptop: VS Code, Dart and a first small program
  • Variables, numbers, text and true/false values, with a simple bill calculator
  • Decisions with if and else, and repeating work with loops
  • Lists and maps: storing many items, like a shop's product list
  • Functions: writing a piece of code once and using it many times
  • Classes and objects: describing a Product, a Student or an Expense in code

Tools & Tech

DartVS CodeDartPad

Learning Outcomes

  • Write small Dart programs on your own, such as a GST bill calculator or a marks list, and read simple code written by others.

Module 2:Git, GitHub and App Design Basics

Weeks 4-5

Core Topics

  • Git in simple words: saving versions of your work so nothing is lost
  • Commit, branch and push, with a GitHub account for every student
  • How to read a pull request and fix a simple merge problem
  • Planning an app on paper: who uses it, what screens it needs, what each screen does
  • Colours, fonts, spacing and buttons that people can tap easily on a small screen
  • Drawing screens in Figma using free templates
  • Making a clickable design for the ordering app before any code is written

Tools & Tech

GitGitHubFigma

Learning Outcomes

  • Keep your code safely on GitHub and design a clean, simple set of app screens that you can build later.

Module 3:Flutter Basics: Screens and Layouts

Weeks 6-7

Core Topics

  • What Flutter is and why one code base can make both Android and iPhone apps
  • Installing Flutter and Android Studio, and running an app on an emulator and on your own phone
  • Widgets: the small building blocks like text, image, button and card
  • Rows, columns and stacks to arrange things on the screen
  • Lists and grids for menus, product lists and photo galleries
  • Working with images, icons, fonts and a colour theme
  • Making the screen fit small and large phones

Tools & Tech

FlutterAndroid StudioVS Code

Learning Outcomes

  • Turn a Figma design into working Flutter screens that run on your own phone.

Module 4:Navigation, Forms and State Management

Weeks 8-9

Core Topics

  • Moving between screens and passing data from one screen to the next
  • Text boxes, drop-downs, date pickers and checking what the user typed
  • What state means: the data on the screen that changes, like a cart count
  • Provider for sharing data across screens in a simple way
  • A short introduction to Riverpod and when people choose it
  • Building an add-to-cart flow with item count and total in rupees
  • Common beginner mistakes with screens refreshing wrongly, and how to find them

Tools & Tech

FlutterProviderRiverpod

Learning Outcomes

  • Build a multi-screen app where a cart, a form and a list all stay in step with each other.

Module 5:REST APIs and Local Storage

Weeks 10-11

Core Topics

  • What an API is: a way for your app to ask a server for data, like a waiter taking your order to the kitchen
  • Reading data in JSON format and turning it into Dart objects
  • Getting and sending data with the http and Dio packages
  • Testing APIs in Postman before using them in the app
  • Showing a loading circle, an error message and an empty list properly
  • Saving small settings on the phone with shared_preferences
  • Saving bigger data on the phone with SQLite so the app works without internet

Tools & Tech

PostmanDioSQLite (sqflite)shared_preferences

Learning Outcomes

  • Fetch live data from a server, show it neatly, and keep important data saved on the phone when there is no network.

Module 6:Firebase: Login, Database and Storage

Weeks 12-14

Core Topics

  • What Firebase is: Google's ready-made backend, so you do not have to build a server first
  • Login with email and password, and with Google sign-in
  • Cloud Firestore: storing orders, users and expenses online
  • Reading data live, so a new order appears without refreshing
  • Uploading photos, such as menu pictures, to Firebase Storage
  • Security rules: making sure one user cannot see another user's data
  • Free plan limits and costs. Google may ask for billing details to switch some parts on, and we explain how to stay safe

Tools & Tech

Firebase AuthenticationCloud FirestoreFirebase StorageFlutterFire

Learning Outcomes

  • Connect an app to Firebase so people can sign up, log in, save their data online and see it on any phone.

Module 7:Notifications and Phone Features

Weeks 15-16

Core Topics

  • Push notifications with Firebase Cloud Messaging: telling a customer 'your order is ready'
  • Local notifications for reminders, such as a daily expense entry
  • Asking the user for permission properly: camera, gallery, location and notifications
  • Picking and showing photos from the camera or gallery
  • Opening Google Maps, calling a number and sharing on WhatsApp from the app
  • Handling the app when the phone is offline or when the user moves it to the background
  • Charts for the expense tracker using a charts package

Tools & Tech

Firebase Cloud Messagingimage_pickerurl_launcherfl_chart

Learning Outcomes

  • Add the features people expect from a real app: notifications, photos, maps links and simple charts.

Module 8:Testing, Release and Store Publishing

Weeks 17-18

Core Topics

  • Why apps break, and how to find bugs using the debugger and logs
  • Writing simple tests for functions and screens with flutter_test
  • Trying the app on different phone sizes and Android versions
  • App name, icon and splash screen
  • Making a signed Android release build (an .aab file)
  • Steps for Google Play Console: app details, screenshots, privacy policy and review
  • Steps for the Apple App Store. A Mac and a paid Apple developer account are needed, so this part is shown as a walkthrough

Tools & Tech

flutter_testFlutter DevToolsGoogle Play ConsoleApp Store Connect

Learning Outcomes

  • Test an app, create a release file and prepare it for the Play Store with everything the review needs.

Module 9:Capstone App and Career Preparation

Weeks 19-20

Core Topics

  • Pick or finish one app: ordering, expense or attendance, with a mentor sign-off
  • Final polish: speed, small bugs, clean screens and a good README on GitHub
  • Recording a short demo video of the app for your portfolio
  • Writing a one-page resume and a LinkedIn profile that shows your GitHub link
  • How to read an app developer job post and what to apply for first
  • Mock interview with questions on Dart, Flutter, state and Firebase
  • How freelance clients ask for apps, and how to explain scope and time to them

Tools & Tech

GitHubLinkedInGoogle Play Console

Learning Outcomes

  • Present one finished app, a GitHub profile and a resume, and answer common interview questions with confidence.

Capstone Projects

Ordering App for a Local Food Business

Problem: A cloud kitchen or sweet shop in Nagpur wants customers to see the menu, add items to a cart and place an order without calling. You build the customer app with login, cart, order history and a notification when the order is ready.

FlutterProviderFirebase AuthenticationCloud FirestoreFirebase Cloud Messaging

Deliverable: A working app on your phone and on GitHub, with a demo video. This is the app you prepare for the Play Store in the release module.

Daily Expense Tracker

Problem: A simple app for a student or a family to note daily spending in rupees, group it by type, and see a monthly chart. It keeps data on the phone, so it works without internet.

FlutterSQLiteshared_preferencesfl_chartLocal notifications

Deliverable: A clean app with add, edit and delete, monthly totals, a chart and a daily reminder, along with a short write-up of how you built it.

Student Attendance App

Problem: A coaching class or college department needs teachers to mark attendance from a phone and parents or students to check it. You build teacher and student logins, class lists and a monthly attendance report.

FlutterRiverpodFirebase AuthenticationCloud FirestoreDio

Deliverable: A two-role app with a clear report screen, security rules on the data, and a project page on GitHub you can share with recruiters.
